# SGLang #17690: Fix missing bias in the matrix multiplication fallback

## Abstract

[PR #17690](https://github.com/sgl-project/sglang/pull/17690) restores bias addition in SGLang's batch-invariant matrix multiplication fallback, fixing garbage inference in the affected Miles deterministic-inference setup.

## Background

When `SGLANG_BATCH_INVARIANT_OPS_ENABLE_MM_FALLBACK_VARIANT=true` and the DeepGEMM path was not selected, `matmul_persistent()` returned `a @ b`, silently dropping the supplied bias. The issue was reported on Ampere/Ada GPUs and reproduced on an NVIDIA A10G with `Qwen2.5-0.5B-Instruct`.

## Design

The [fallback implementation](https://github.com/sgl-project/sglang/blob/fa8d225c7dffcf08d3b182e6fcdb1a1b2bff1172/python/sglang/srt/batch_invariant_ops/batch_invariant_ops.py#L265) now adds the optional bias before returning:

```python
if _ENABLE_MM_FALLBACK_VARIANT:
    out = torch.einsum("ik,kj->ij", a, b)
    if bias is not None:
        out += bias
    return out
```

This restores the expected `a @ b + bias` behavior for biased linear layers.

## Benchmark result

The PR reports these `few_shot_gsm8k` results:

| Configuration | Main accuracy | PR accuracy | Main invalid rate | PR invalid rate |
| --- | ---: | ---: | ---: | ---: |
| Default: Qwen2-7B-Instruct | 83.5% | 81.0% | 0.0% | 0.0% |
| Miles: Qwen2.5-0.5B-Instruct | 0.0% | 33.0% | 99.5% | 1.0% |

The rows use different models and are separate before/after comparisons. The Miles result shows recovery from broken fallback behavior; the default setup shows no accuracy improvement. No latency or throughput measurements were reported.

## Downstream impact / feedback

- Restores usable output for the affected Miles reproducibility example and models using biased linear layers through this fallback.
- The author reported that a table-leg arithmetic prompt changed from garbled text to a coherent answer of **310**.
- Validation consists of reported reproduction and accuracy runs; the PR added no automated regression test.
